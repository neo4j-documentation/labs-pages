The Neo4j plugin provides indexer and retriever implementations that use the Neo4j graph database for vector search capabilities.

Neo4j is a graph database that combines the power of graph relationships with vector search capabilities. It enables you to store documents as nodes with vector embeddings while maintaining rich relationships between entities, making it ideal for knowledge graphs, recommendation systems, and complex AI applications that need both semantic search and graph traversal.

The library allows using Neo4j as a vector storage and retrieval backend. It exposes references for indexing and retrieval via `neo4jIndexerRef` and `neo4jRetrieverRef`.

Install the required dependencies in your project:

[source,bash]
----
npm install genkit genkitx-neo4j @genkit-ai/googleai neo4j-driver

== Configuration

To use this plugin, specify it when you initialize Genkit. You must specify a Neo4j index ID and the embedding model you want to use.

[source,typescript]
----
import { genkit } from 'genkit';
import neo4j from 'genkitx-neo4j';
import { googleAI } from '@genkit-ai/googleai';

const ai = genkit({
  plugins: [
    googleAI(),
    neo4j([
      {
        indexId: 'my-vector-index',
        embedder: googleAI.embedder('gemini-embedding-001'),
      },
    ]),
  ],
});
----

### Connection Configuration

There are two ways to configure the Neo4j connection.

**1. Using environment variables:**
If no parameters are passed, the plugin will look for the following environment variables:
[source,bash]
----
NEO4J_URI=bolt://localhost:7687  # Neo4j's binary protocol
NEO4J_USERNAME=neo4j
NEO4J_PASSWORD=password
NEO4J_DATABASE=neo4j  # Optional: specify database name
----

**2. Using the `clientParams` option:**
You can explicitly pass the connection configuration in your code:
[source,typescript]
----
neo4j([
  {
    indexId: 'my-vector-index',
    embedder: googleAI.embedder('gemini-embedding-001'),
    clientParams: {
      url: 'bolt://localhost:7687',
      username: 'neo4j',
      password: 'password',
      database: 'neo4j', // Optional
    },
  },
])
----
*Note: The `bolt://` protocol is Neo4j’s proprietary binary protocol designed for efficient client-server communication.*

### Full Configuration Options

The Neo4j plugin initialization accepts a rich set of properties (`Neo4jParams`) to map the vector index exactly to your graph domain:

* `indexId`: (required) The name of the vector index to use in Neo4j.
* `embedder`: (required) The Genkit embedding model to use.
* `clientParams`: (optional) Neo4j connection configuration object.
* `label`: (optional) Custom node label (defaults to `indexId`).
* `textProperty`: (optional) The node property storing the text chunk (defaults to `text`).
* `embeddingProperty`: (optional) The node property storing the vector (defaults to `embedding`).
* `idProperty`: (optional) The node property storing the unique ID (defaults to `id`).
* `retrievalQuery`: (optional) A custom Cypher query to run during retrieval.
* `searchType`: (optional) Use `"hybrid"` for combined vector and full-text search.
* `fullTextIndexName`: (optional) Custom name for the full-text index in hybrid search.
* `fullTextQuery`: (optional) Baseline query parameter for the full-text component.
* `searchStrategy`: (optional) The cypher strategy to use (e.g., `MatchSearchClauseStrategy` for 2026.01+ native filtering).
* `filterMetadata`: (optional) Array of string properties to explicitly index for native filtering.
* `ragModel`: (optional) The LLM model reference (needed for HyDE GraphRAG capabilities).
* `customGraphRagConfigs`: (optional) Object mapping custom GraphRAG topologies.

== Example: Standalone Usage

This example demonstrates how to configure and use the Genkit Neo4j plugin to index and retrieve documents.

[source,typescript]
----
import { Document } from 'genkit';
import { neo4jIndexerRef, neo4jRetrieverRef } from 'genkitx-neo4j';

export async function processDocuments(ai: any) {
  const INDEXER_REF = neo4jIndexerRef({ indexId: 'my-vector-index' });
  const RETRIEVER_REF = neo4jRetrieverRef({ indexId: 'my-vector-index' });
  
  // 1. Create a new document
  const doc = new Document({
    content: [{ text: 'Neo4j is a highly scalable native graph database.' }],
    metadata: { category: 'database', uniqueId: 'doc-1' },
  });

  // 2. Index the document in Neo4j
  await ai.index({ 
    indexer: INDEXER_REF, 
    documents: [doc] 
  });
  console.log('Document indexed successfully.');

  // 3. Retrieve the document using the retriever reference
  const docs = await ai.retrieve({
    retriever: RETRIEVER_REF,
    query: 'What is Neo4j?',
    options: { k: 5 },
  });

  return docs.map(d => d.content[0].text);
}
----

== Advanced Retrieval and Graph Features

### Custom Entity and Label Properties

Instead of being constrained to a predefined database schema, you can configure the plugin to use custom node labels, ID fields, and properties for text and embeddings. This enables you to integrate embeddings into an existing Neo4j domain model seamlessly without altering your graph structure.

[source,typescript]
----
neo4j([
  {
    indexId: 'articles-idx', 
    embedder: googleAI.embedder('gemini-embedding-001'),
    label: 'Article', // Index standard nodes with the 'Article' label
    textProperty: 'bodyContent',
    embeddingProperty: 'semanticVector',
    idProperty: 'articleId',
  },
])
----

### Metadata Filtering (Native Neo4j 2026.01+ Syntax)

The plugin supports advanced metadata filtering, allowing retrieval queries to include structured constraints alongside semantic similarity. Using Neo4j 2026.01+ syntax under the hood (`MatchSearchClauseStrategy`), the filtering logic is resolved directly within the vector index via the `SEARCH ... IN VECTOR INDEX` clause.

To optimize performance and instruct Neo4j to build index structures specifically for those fields, pass the `filterMetadata` array.

[source,typescript]
----
import { MatchSearchClauseStrategy } from 'genkitx-neo4j';

// Plugin initialization
neo4j([
  {
    indexId: 'company-docs',
    embedder: googleAI.embedder('gemini-embedding-001'),
    searchStrategy: new MatchSearchClauseStrategy(), // Use the 2026.01 syntax
    filterMetadata: ['department', 'status'], // Explicitly optimize index for these properties
  },
])

// Retrieval Usage
import { neo4jRetrieverRef } from 'genkitx-neo4j';

export async function retrieveActiveItDocs(ai: any, query: string) {
  const docs = await ai.retrieve({
    retriever: neo4jRetrieverRef({ indexId: 'company-docs' }),
    query: query,
    options: {
      k: 10,
      filter: { department: 'IT', status: 'active' }, // Applied directly in the vector index lookup
    },
  });
  return docs;
}
----

### Hybrid Search (Vector + Full-Text)

Hybrid search blends exact full-text keyword matching with the semantic ranking of vector search. This is incredibly useful when queries contain domain-specific jargon, part numbers, or IDs that must match exactly.

*Note: Metadata filtering cannot be used in combination with the hybrid search approach. Attempting to pass `filter: {...}` while `searchType: 'hybrid'` is active will throw an error.*

[source,typescript]
----
// Plugin initialization
neo4j([
  {
    indexId: 'hybrid-idx',
    embedder: googleAI.embedder('gemini-embedding-001'),
    searchType: 'hybrid', // Enable the hybrid fallback
    fullTextIndexName: 'customFullTextIndexName', // Optional: override default name
    fullTextQuery: 'documentation', 
  },
])

// Retrieval Usage
export async function retrieveWithHybridSearch(ai: any, query: string) {
  const docs = await ai.retrieve({
    retriever: neo4jRetrieverRef({ indexId: 'hybrid-idx' }),
    query: query,
    options: { k: 5 },
  });
  return docs;
}
----

### Custom Retrieval Queries

If standard vector similarity isn't enough, developers can supply custom Cypher logic via the plugin settings using `retrievalQuery`. This is perfect for executing specialized metadata lookups, custom traversals, and returning calculated properties alongside embeddings.

[source,typescript]
----
neo4j([
  {
    indexId: 'custom-query-idx',
    embedder: googleAI.embedder('gemini-embedding-001'),
    // Override the default RETURN statement. 
    // Return the text, plus any graph-derived metrics or constants
    retrievalQuery: "RETURN node.text AS text, {pagerank: node.pagerankScore, customFlag: '1'} AS metadata"
  },
])
----

### GraphRAG Capabilities

The plugin natively bundles advanced **GraphRAG** strategies. These strategies exploit the connected nature of your graph to provide significantly richer context to the LLM compared to simple vector similarity.

Supported built-in strategies include:
* **Parent-Child Retriever:** Matches against dense, smaller text chunks but returns the broader context (the "parent" document).
* **Hypothetical Question Retriever (HyDE):** Generates a hypothetical ideal answer via an LLM, then uses that to query the vector space.
* **Generic / Custom GraphRAG:** Allows defining arbitrary multi-hop relationships (e.g., fetching sibling documents or related concepts).

[source,typescript]
----
import { 
  neo4jParentChildRetrieverRef, 
  neo4jHyDERetrieverRef, 
  neo4jCustomRetrieverRef 
} from 'genkitx-neo4j';

// 1. Defining a Custom GraphRAG Topology during Initialization
neo4j([
  {
    indexId: 'my-graphrag-index',
    embedder: googleAI.embedder('gemini-embedding-001'),
    customGraphRagConfigs: {
      'sibling-search': {
        systemPrompt: "Use the sibling documents to answer the question.",
        idMetadataKey: "docId",
        cypherIdParamName: "startIds",
        // Traverse custom relationships
        cypherQuery: `
          MATCH (start:Document)-[:SIBLING_OF]->(sibling:Document)
          WHERE start.id IN $startIds
          RETURN sibling.text AS siblingText
        `,
        cypherReturnTextField: "siblingText"
      }
    }
  },
])

// 2. Retrieval usage
export async function graphRagRetrieval(ai: any, userQuery: string) {
  
  // Example A: Parent-Child strategy
  const parentDocs = await ai.retrieve({
    retriever: neo4jParentChildRetrieverRef({ indexId: 'my-graphrag-index' }),
    query: userQuery,
    options: { k: 3 }
  });

  // Example B: HyDE strategy
  const hydeDocs = await ai.retrieve({
    retriever: neo4jHyDERetrieverRef({ indexId: 'my-graphrag-index' }),
    query: userQuery,
    options: { k: 3 }
  });

  // Example C: Calling our Custom RAG (Sibling Search)
  const customRagDocs = await ai.retrieve({
    retriever: neo4jCustomRetrieverRef({ indexId: 'my-graphrag-index', name: 'sibling-search' }),
    query: userQuery,
    options: { k: 3 }
  });

  return customRagDocs;
}

### Genkit Chat Memory with Neo4j

The plugin provides a `Neo4jSessionStore`, establishing a robust Session Persistence layer mapped natively to Neo4j. The module stores conversation states and threads as connected subgraphs, making it easy to persist history, manage context window sizes, and run graph algorithms over conversation history.

You can fully customize the Node Labels (`sessionLabel`, `messageLabel`) and Relationship Types (`nextMessageRelType`, `lastMessageRelType`).

[source,typescript]
----
import { Neo4jSessionStore } from 'genkitx-neo4j';
import { gemini15Flash } from '@genkit-ai/googleai';

export async function startPersistentChat(ai: any, sessionId: string, userMessage: string) {
  
  // Configure the Neo4j backed session memory with Custom Schema
  const neo4jStore = new Neo4jSessionStore({
    url: 'bolt://localhost:7687',
    username: 'neo4j',
    password: 'password',
    sessionLabel: 'CustomSession',       // Defaults to 'GenkitSession'
    messageLabel: 'CustomMessage',       // Defaults to 'Message'
    nextMessageRelType: 'THREAD_NEXT',   // Defaults to 'NEXT'
    lastMessageRelType: 'THREAD_HEAD'    // Defaults to 'LAST_MESSAGE'
  });
  
  // Control Token Bloat: Only feed the last 10 messages into the LLM context
  neo4jStore.setWindowSize(10); 

  // Initialize the chat session
  const chat = ai.chat({
    model: gemini15Flash,
    store: neo4jStore,
    sessionId: sessionId
  });

  const response = await chat.send(userMessage);
  console.log(response.text);

  // If you need to wipe a user's memory/graph-nodes programmatically:
  // await neo4jStore.clear(sessionId);
}

== Functionality Includes

* `neo4jIndexerRef` & `neo4jRetrieverRef` - Core predefined references for indexing and retrieving documents in Neo4j.
* Full integration with Genkit and Google AI embedders.
* Vector embeddings natively stored in Neo4j properties.
* Support for Custom Entity/Label Properties to match existing graph schemas.
* Metadata Filtering heavily optimized using Neo4j 2026.01+ native in-index filtering syntax (`MATCH ... SEARCH node IN VECTOR INDEX`).
* Hybrid Search combining semantic similarity with full-text scoring.
* Custom Retrieval Queries mapped dynamically via Cypher.
* Native GraphRAG capabilities (Parent-Child, Hypothetical Question retrievers, Custom Configurations) bundled with LLM ingestion tools.
* Neo4j-backed Chat Memory/Session Persistence Module with customizable window size limits, specific labels, and custom relationship routing.
